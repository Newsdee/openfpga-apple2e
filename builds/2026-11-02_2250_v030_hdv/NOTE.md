# Build 2026-11-02 2250 - v0.3.0 HDV read-only milestone

First 0.3.0 release. Version bumped 0.2.7 -> 0.3.0 (SemVer MINOR: the HDV/HDD
read-only capability is a new, backward-compatible feature; per Analogue docs
"SemVer is highly encouraged"). date_release 2026-11-02. framework.version_required
stays 1.1 (HDV uses the existing deferload protocol).

## What's in it
- **Item A - HDV auto boot** (`apf_stream_video_top.v`): selecting an HDV in the
  picker now auto cold-boots into it (no OSK Reset). The 0x008A mount edge feeds
  a ~203 ms settle delay (`HDV_REBOOT_SETTLE` localparam) so the host finishes
  arming the HD before the same CLR+HOLD cold reset OSK Reset uses. Power-on
  blanking (~175 ms) suppresses the initial double-mount; WOZ mount edge stays
  immediate. Gated by the "Reboot on load" interact option (id 2) - must be ON.
  (The 1917 raw-edge attempt fired mid-handshake -> black idle; the settle delay
  is the fix.)
- **Item B - drive lamps, two-tone** (`sdram_status_overlay.v`): the three J9
  lamps (top-right, not gated by OVL_DBG) with ~140 ms monostable holds so short
  HD fetch bursts (one block walk ~36 us, beam passes once/frame) are visible:
    green     = HD read in flight   (bridge state 1/2/3)
    bright red= floppy READ         (drv_ack)
    dark  red = floppy SPIN         (drv_active || drv_motor)
    white     = HD block completed  (fetch_cnt changed)
  Media is distinguishable at a glance: red family = floppy, green/white = HD.
- **Core icon** (`icon.bin`, new): the "newsdee" author mark, 36x36 B&W ->
  16-bit monochrome, rotated 90 CCW, little-endian (2592 bytes). Generated by
  `tools/make_icon.py`. Auto-detected by the framework (no core.json field).
  Byte order is the one thing to confirm on hardware: if the icon renders
  BLANK, the device reads big-endian - regenerate with `tools/make_icon.py ... be`.
